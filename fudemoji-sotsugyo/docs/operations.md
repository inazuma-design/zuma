# 運用手順（ZUMA 向け）

受講生は、これまでどおり LINE のオープンチャット（ノート）に作品を出すだけです。登録は ZUMA がパソコンで行います。フォームは使いません（作ってはあるので、使いたくなったら使えます）。

## 作品を登録する（ZUMA、パソコン）

1 作品につき「画像をフォルダに入れる」「シートに 1 行書く」の 2 つだけです。

1. LINE のノートから作品画像を保存する
2. 画像ファイルの名前を分かりやすく変える。例: `はなこ_希望.jpg`（同じ名前のファイルを 2 つ作らない）
3. Drive のフォルダ「デジタル筆文字 2期 卒業制作」に入れる（まとめてドラッグでよい）
   https://drive.google.com/drive/folders/139mA7utKwxHldd37ESj-92B2XzUpXuqd
4. 回答スプレッドシートの「フォームの回答 1」シートに 1 行足す
   https://docs.google.com/spreadsheets/d/1XcH-tcuxQILc5KFo8c6iDm20vMgLzsmWAqsP3huecF4/edit

   | 列 | 入れるもの |
   |---|---|
   | タイムスタンプ | 提出日時。`2026/11/12 20:30` のように書く（提出順の根拠。空だと先頭に寄る） |
   | ニックネーム | 講座で使っている呼び名（本名は入れない） |
   | 作品名 | 受講生がつけた作品名 |
   | ひとこと | 受講生のコメント。無ければ空欄。セル内の改行はそのまま出る |
   | Instagram | 受講生が載せてよいと言った場合だけ。`@名前` でも URL でもよい |
   | 講座・期 | `デジタル筆文字 2期` |
   | 作品画像 | **手順 2 のファイル名**（例 `はなこ_希望.jpg`）。Drive のリンクでもよい |

5. これで完了。毎日 0 時すぎと 12 時すぎに自動で反映されます（公開日の 12/1 より前は表に出ません）。すぐ確認したいときは GitHub の Actions → `fudemoji-sotsugyo` → Run workflow

ビルドのログに `画像「〇〇.jpg」が共有フォルダに見つかりません` と出たら、ファイル名の打ち間違いか、フォルダに入っていないかのどちらかです。

### 受講生にお願いすること

ノートに出すときに「作品名」「ひとこと（任意）」、載せてよければ「Instagram」を添えてもらう。無ければ ZUMA が本人に確認します。

## 先生の作品をファーストビューに出す（ZUMA）

トップページと予告ページの最初に、先生の作品を額装して大きく出せます（受講生の一覧とは別扱い）。

1. 共有フォルダの中にサブフォルダ「先生」を作り、先生の作品画像を入れる（例 `hira_春.jpg`）。サブフォルダの中はシートに自動で行が増えません
2. `site.config.json` の `hero.image` を書く
   ```json
   "image": { "file": "hira_春.jpg", "caption": "筆文字似顔絵師Hira「春」", "alt": "ひら先生の作品「春」" }
   ```
3. 作り直す。トップの OGP 画像（LINE に貼ったときのカード）もこの作品になります

`file` を空にすれば、作品なしのレイアウトに戻ります。

## 修正する（ZUMA）

フォームの回答は Google スプレッドシートに 1 行ずつ入ります。セルを直接書き換えれば、次のビルドでサイトに反映されます。

| したいこと | 操作 |
|---|---|
| 作品名・ニックネーム・ひとことを直す | 該当セルを書き換える |
| 画像を差し替える | フォルダの画像を同じファイル名で置き換える（URL は変わらない）。別名にしたときは「作品画像」のセルも直し、URL を保ちたければ「作品ID」に元の値を入れる |
| 並び順を変える | 「表示順」列に数字を入れる（1, 2, 3 …）。数字のある行が先、残りは提出順 |
| 非掲載にする | 「掲載」列に `×` を入れる（空欄＝掲載） |
| 掲載を戻す | `×` を消す |
| すぐ反映したい | GitHub の Actions → `fudemoji-sotsugyo` → Run workflow |
| トップページの OGP 画像に代表作品を出す | 作者の同意を得てから、`site.config.json` の `representativeWorkId` に、その作品の Drive ファイル ID（画像列の `id=` の後ろ）または「作品ID」列の値を入れて push |

### シートの列

列は見出しの文字で探すので、順番が変わっても大丈夫です。

| 列 | 見出し | 誰が入れる | 備考 |
|---|---|---|---|
| A | タイムスタンプ | ZUMA | 提出順の根拠。`2026/11/12 20:30` の形 |
| B | ニックネーム | ZUMA | 必須 |
| C | 作品名 | ZUMA | 必須 |
| D | ひとこと | ZUMA | 任意。1000 文字まで |
| G | 作品画像 | ZUMA | 必須。フォルダ内のファイル名、または Drive のリンク |
| E | Instagram | ZUMA | 任意。`@name` か instagram.com の URL だけ有効 |
| F | 講座・期 | ZUMA | 「デジタル筆文字 2期」以外の行は出ない |
| I | 表示順 | ZUMA | 任意。数値 |
| J | 掲載 | ZUMA | 空欄＝掲載、`×`＝除外 |
| K | 作品ID | ZUMA | 任意。入れると URL がこの値から作られる（画像を差し替えても URL を保ちたいとき） |

### 1人1作品の確認

同じニックネームが 2 行あると、ビルドのログに警告が出ます（両方とも掲載されます）。意図した重複でなければ、どちらかの「掲載」に `×` を入れてください。機械的には判定しません。

## 掲載の取り下げ依頼が来たら（ZUMA）

1. 「掲載」に `×` を入れる
2. Actions を手動実行する（次の定時を待たなくてよい）
3. 作品ページと画像は次のビルドで消えます。LINE や SNS に貼られたカードのキャッシュは、相手側の仕様で残ることがあります

## ビルドの結果を見る（ZUMA）

GitHub の Actions → `fudemoji-sotsugyo` → 最新の実行 → `Build site`。

- `⚠ 行 12: 作品画像が空のためスキップしました` のような警告が、行番号つきで出ます
- `取得元: service-account ／ 候補 30 作品 ／ 判定時刻 … ／ 公開` の行で、公開状態と件数が分かります
- 赤く失敗している場合は、シートの共有設定か Secrets を疑ってください（[deployment.md](deployment.md)）。失敗しても前回の公開物は残ります
