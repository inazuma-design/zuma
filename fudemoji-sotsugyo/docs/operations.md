# 運用手順（ゆゆさん・ZUMA 向け）

このサイトは「Google フォームに入力すると、半日以内に自動でサイトに載る」仕組みです。GitHub を触る必要はありません。

## 作品を登録する（ゆゆさん）

受講生が LINE ノートに出した作品を、1作品につき1回、フォームに入力します。

1. ZUMA から届いた **登録フォームの URL** をスマホで開く（Google アカウントでログインしている必要があります）
2. 次を入力する

   | 項目 | 入れるもの |
   |---|---|
   | ニックネーム | 受講生が講座で使っている呼び名（本名は入れない） |
   | 作品名 | 受講生がつけた作品名 |
   | ひとこと | 受講生のコメント。無ければ空欄でよい。改行はそのまま入れてよい |
   | 作品画像 | 画像を1枚選ぶ（JPEG か PNG。10MB まで）。LINE から保存した画像で OK |
   | Instagram | 受講生が載せてよいと言った場合だけ。`@名前` でも URL でもよい |
   | 講座・期 | 「デジタル筆文字 2期」を選ぶ |
3. 送信する

これで完了です。サイトには **毎日 0 時すぎと 12 時すぎ** に反映されます（公開日の 12/1 より前は、入力しても表に出ません。公開日になると自動で表示されます）。

困ったとき

- 画像が選べない: iPhone の「写真」に保存されているか確認。HEIC 形式は NG なので、LINE から保存し直すか、スクリーンショットではなく元の画像を使う
- 同じ人の作品を 2 回送ってしまった: ZUMA に連絡。スプレッドシートで片方を非掲載にします
- 入力ミスに気づいた: ZUMA に連絡。スプレッドシートで直せます（フォームを送り直す必要はありません）

## 修正する（ZUMA）

フォームの回答は Google スプレッドシートに 1 行ずつ入ります。セルを直接書き換えれば、次のビルドでサイトに反映されます。

| したいこと | 操作 |
|---|---|
| 作品名・ニックネーム・ひとことを直す | 該当セルを書き換える |
| 画像を差し替える | 受講生に正しい画像をもらい、フォームから **新しい行として送信** し、古い行の「掲載」に `×` を入れる。URL を変えたくない場合は下の「作品ID」を使う |
| 並び順を変える | 「表示順」列に数字を入れる（1, 2, 3 …）。数字のある行が先、残りは提出順 |
| 非掲載にする | 「掲載」列に `×` を入れる（空欄＝掲載） |
| 掲載を戻す | `×` を消す |
| すぐ反映したい | GitHub の Actions → `fudemoji-sotsugyo` → Run workflow |
| トップページの OGP 画像に代表作品を出す | 作者の同意を得てから、`site.config.json` の `representativeWorkId` に、その作品の Drive ファイル ID（画像列の `id=` の後ろ）または「作品ID」列の値を入れて push |

### シートの列

フォームが自動で作る列（A〜G）に、手動で H〜J を足します。列は見出しの文字で探すので、順番が変わっても大丈夫です。

| 列 | 見出し | 誰が入れる | 備考 |
|---|---|---|---|
| A | タイムスタンプ | 自動 | 提出順の根拠 |
| B | ニックネーム | フォーム | 必須 |
| C | 作品名 | フォーム | 必須 |
| D | ひとこと | フォーム | 任意。1000 文字まで |
| E | 作品画像 | フォーム | 必須。Drive のリンクが入る |
| F | Instagram | フォーム | 任意。`@name` か instagram.com の URL だけ有効 |
| G | 講座・期 | フォーム | 「デジタル筆文字 2期」以外の行は出ない |
| H | 表示順 | ZUMA | 任意。数値 |
| I | 掲載 | ZUMA | 空欄＝掲載、`×`＝除外 |
| J | 作品ID | ZUMA | 任意。入れると URL がこの値から作られる（画像を差し替えても URL を保ちたいとき） |

### 1人1作品の確認

同じニックネームが 2 行あると、ビルドのログに警告が出ます（両方とも掲載されます）。意図した重複でなければ、どちらかの「掲載」に `×` を入れてください。機械的には判定しません。

## 掲載の取り下げ依頼が来たら（ZUMA）

1. 「掲載」に `×` を入れる
2. Actions を手動実行する（次の定時を待たなくてよい）
3. 作品ページと画像は次のビルドで消えます。LINE や SNS に貼られたカードのキャッシュは、相手側の仕様で残ることがあります

## ビルドの結果を見る（ZUMA）

GitHub の Actions → `fudemoji-sotsugyo` → 最新の実行 → `Build site`。

- `⚠ 行 12: 作品画像が空のためスキップしました` のような警告が、行番号つきで出ます
- `取得元: service-account ／ 候補 30 作品 ／ 判定時刻 … ／ 公開` の行で、公開状態と件数が分かります
- 赤く失敗している場合は、シートの共有設定か Secrets を疑ってください（[deployment.md](deployment.md)）。失敗しても前回の公開物は残ります
